# 2. 데이터 형식 풀기

형식은 **파일만 보고 추측하지 말고, 그 파일을 읽는 원작 함수를 찾아서** 푸는 것이 가장 빠르고 정확합니다. `strings.txt` 에서 파일 이름(`"DATA.E5"` 등)을 찾으면 읽는 함수가 나옵니다.

## 2.1 KOEI Ls12 압축 묶음 (`*.E5`)

코에이 게임에 흔한 형식입니다. 구현: `crates/ekd5/src/ls12.rs`, 시제품: `re/tools/ls12.py`.

```
0x000  "Ls12" + 12바이트
0x010  바이트 치환 사전 256바이트
0x110  항목 표: (압축 크기, 원래 크기, 오프셋) 빅엔디언 u32 × 3 … 압축 크기 0 이면 끝
```

압축 해제:
- MSB 부터 읽는 비트열입니다.
- **부호(code)**: 앞에 1 이 n 개 + 0 하나, 그다음 n+1 비트. 값 = 앞부분 + 뒷부분 (가변 길이 정수).
- 값 < 256 이면 `사전[값]` 한 바이트를 냅니다.
- 그 외는 거리 = 값 − 256, 길이 = 다음 부호 + 3 만큼 앞의 출력을 복사합니다 (LZ77).
- 압축 크기 = 원래 크기면 무압축입니다.

## 2.2 팔레트

원작은 8비트(256색) 윈도 화면입니다. 구현: `palette.rs`.
- 3바이트가 **B, R, G** 순서입니다 (RGB 가 아님). 각 값을 4비트로 잘라 씁니다.
- 0..9, 246..255 번은 윈도 시스템 색 자리라 원작이 바꾸지 않습니다. 시스템 고정 20색을 그대로 채워야 글자색 등이 맞습니다.
- 장면마다 팔레트가 다릅니다 (이야기 `PMPALET`, 전투 `SPALET`, 제목 `LOGO_P`).

> 함정: 색 순서가 틀리면 그림이 "대충 맞는 듯" 보여서 늦게 발견합니다. 피부색과 하늘색으로 확인하세요.

엔진은 화면을 **팔레트 번호 버퍼(640×480 바이트)** 로 그리고, 마지막에 RGBA 로 바꿉니다. 원작의 "팔레트 번호로 하는 효과"(어둡게, 반투명, 바둑판 무늬)를 그대로 옮기기 쉽습니다.

## 2.3 글꼴

원작 글꼴 파일을 그대로 씁니다 (`font.rs`).
- 한글·전각 (EUC-KR): `ALL_FONT.16P`, 글자당 30바이트 (코드 u16 + 14행 × 16비트).
  색인 = (상위 − (상위 < 0xB0 ? 0xA1 : 0xA4)) × 94 + (하위 − 0xA1)
- 반각 (ASCII): `ANKFONT.DAT`, 글자당 16바이트 (8×16).
- 문자열은 EUC-KR 입니다. Rust 에서는 `encoding_rs` 로 풉니다.

원작이 화면에 크게 쓰는 제목 글자는 윈도 글꼴(굴림 굵게)이라 파일이 없습니다. 웹에서는 캔버스로 그 글자를 그려 엔진에 마스크로 넘깁니다 (6장 `@txt/`).

## 2.4 스프라이트

모두 무압축 8비트 그림이며 Ls12 묶음 안에 있습니다. 투명색은 0번입니다.

| 파일 | 크기 | 배치 |
|---|---|---|
| `UNIT_MOV.E5` | 48×48 × 11장 (0x900 바이트/장) | 아래 걷기 0-1, 위 2-3, 옆 4-5, 서 있기(정면·뒤·옆) 6-8, 약함 9-10 |
| `UNIT_ATK.E5` | 64×64 × 12장 | 아래 0-3, 위 4-7, 옆 8-11 (공격 동작) |
| `UNIT_SPC.E5` | 48×48 × 5장 | 막기 0-2, 맞음 3, 승리 4 |
| `FACE.E5` | 64×80 | 얼굴 |
| `PMAPOBJ.E5` | 48×64 × 20장 | 이야기 장면 인물 |

**한 장의 배치를 모를 때**: 원작이 그 장을 그리는 함수에서 오프셋을 봅니다. 예: `FUN_00481f60(buf, 0x3600, …)` 이면 0x3600 / 0x900 = 6번 장입니다.

## 2.5 표 데이터 (`DATA.E5`)

| 항목 | 기록 크기 | 내용 |
|---|---|---|
| 0 | 32바이트 | 인물: 이름 13, 얼굴, 그림, 능력 5, HP, MP, 직업, 레벨, 장비 3 |
| 1 | 25바이트 | 아이템: 이름 17, 종류, 특수 종류, 가격, 그림, 기본치, 특수치, 성장치, 구분 |
| 3 | 27바이트 | 직업: 이동력, 공격 범위, 성장 등급, 장비 가능 표 |
| 4 | 60바이트 × 병종 | 지형 효과 30 + 이동 비용 30 |
| 5 | 70바이트 | 책략 |

설명 글은 `IMSG.E5` 에 **216바이트 고정 기록**으로 들어 있습니다 (아이템 0.., 책략 150.., 부대특성 350.., 장수열전 450+인물, 퇴각 대사 650+인물, 회심 외침 700..).

### 함정: 메모리 기록과 파일 기록의 칸 위치가 다르다

원작은 파일을 읽어 **다른 배치의 메모리 구조체**로 옮겨 담습니다. 그래서 디컴파일 코드의 `this + 0x26` 을 파일의 0x26 번째 바이트로 착각하면 틀립니다.

- 아이템: 메모리 `+0x12` (가격) = 파일 `+19`, 메모리 `+0x14` (특수 종류) = 파일 `+18`
- 인물: 메모리 `+0x26` (목소리 종류) = 파일 `+16`

**해결**: 파일 → 메모리로 옮겨 담는 함수(로더)를 한 번 찾아 대응표를 만들어 둡니다. 조조전 인물은 `FUN_00408fd5` 가 그 함수였습니다.

## 2.6 지도와 좌표

- 이야기 배경: `MMAP` 8×8 타일, 등각 좌표 `sx = (x − y)·8 + 312`, `sy = (x + y)·4 − 152`
- 전투: 칸 48×48, `HMnn` 지도 + `HEXZMAP` 지형 번호 + `SPALET` 팔레트

자세한 메모는 `AGENTS.md` 의 "형식 요약"에 있습니다.

## 2.7 소리

- 효과음: 번호 n < 100 이면 `SEnn.WAV`, 100+ 는 `SE_M_nn` (책략), 200+ 는 `SE_E_nn`
- 배경음악: 원작은 **CD 오디오 트랙**을 틉니다. 트랙 = 스크립트 인자 + 2. `scripts/extract-cd.py` 가 CD 이미지에서 트랙을 꺼내 `BGMnn.m4a` 로 만듭니다.
- 동영상: CD 의 AVI(Cinepak) → `ffmpeg` 로 mp4.
