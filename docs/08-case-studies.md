# 8. 사례 연구

실제로 있었던 버그와 누락을, 증상에서 원작 코드까지 추적한 과정입니다. 원작 함수 주소는 `EKD5.EXE` 한국어판 기준입니다.

---

## 사례 1. 조조가 청룡언월도를 들고 있다

**증상**: 첫 장면부터 조조의 무기가 청룡언월도입니다. 원작은 의천검입니다.

**추적**
1. 첫 장면 스크립트의 장비 명령(op3e)은 인자로 `25` 를 줍니다. 아이템 표의 25번이 청룡언월도, 23번이 의천검입니다.
2. op3e 처리 함수 → `FUN_004081dc` 를 읽습니다.
   ```c
   if (slot == 0) value = value - 2;       // 무기
   else if (slot == 1) value = value + 0x24; // 방어구
   else value = value + 0x33;              // 보조
   ```
3. 칸마다 번호 변환이 있었습니다. 우리 엔진은 번호를 그대로 썼습니다. 이어서 같은 함수에서 "레벨 0 = 장수 레벨로 자동", "직업이 못 쓰면 무시" 규칙도 찾았습니다.

**수정**: `Officer::script_equip` 에 변환과 규칙을 옮겼습니다. 이미 잘못 저장된 게임은 불러올 때 `fix_legacy_gear` 로 교정합니다.

**교훈**: 스크립트 숫자 인자에는 숨은 변환이 있을 수 있습니다. 처리 함수를 끝까지 읽어야 합니다.

## 사례 2. 여포에게 데미지가 안 들어간다

**요청**: "원래 난이도인지 버그인지 **체크만** 해 줘."

**추적**
1. 데미지 공식 `FUN_0043dd5b` 를 우리 구현과 한 줄씩 대조했습니다. 같았습니다.
2. 여포의 레벨은 스크립트 부대 목록 명령(op47)이 "아군 평균 + 6" 으로 정합니다. 그 평균을 내는 `FUN_0041adb4` 와 부대 배치 `FUN_00414d74` 를 읽었습니다.
   ```c
   base = army_average() + DAT_004a159b;   // ← 이 값은?
   ```
3. `DAT_004a159b` 를 쓰는 곳을 찾으니 전투 설정 명령(op45)의 **3번 인자**였습니다. 50 이하면 +값, 그 위면 −(값−50) 입니다. 58개 전투 모두 52, 즉 **−2** 였습니다.
4. 또 하나: 평균을 내는 대상이 원작은 **출진한 장수들**인데 우리는 동료 전체였습니다.

**결과 보고**: 데미지 공식은 원작과 같고, 여포가 원래 강한 것은 맞음. 다만 모든 전투의 적이 원작보다 2레벨 높았음.

**사람의 판단**: "원작 난이도로 바꿔 줘." → 두 가지를 고쳤습니다.

**교훈**: 명령 인자를 하나라도 무시하면 게임 전체의 균형이 조용히 틀어집니다. "체크만"을 따로 요청하면 판단과 수정을 나눌 수 있습니다.

## 사례 3. 데미지 숫자가 빠졌다

**증상**: 원작은 맞은 부대 위에 데미지 숫자가 떴습니다.

**추적**
1. 앞서 원작의 HP 창(`FUN_00452964`)을 옮기면서, AI 가 "HP 창이 데미지를 보여 주니 숫자는 필요 없다"고 판단해 꺼 두었습니다.
2. 공격 연출 함수 `FUN_00404849` 를 단위별로 읽었습니다. 27단위 중 **17번째 단위**에 `FUN_00451ad1(맞은 부대, 데미지, 0x12, 0x18)` 를 부릅니다.
3. `FUN_00451ad1` 은 숫자를 `0x82, 숫자+0x1F` 로 바꿉니다 (Shift-JIS 전각 숫자). 그다음 부대 칸 위에 글자색 0x12, 테두리 0x18 로 씁니다. MP 데미지는 색 0x45 입니다.

**수정**: 엔진 틱으로 환산해(17단위 → 26틱) 그 시점부터 타격이 끝날 때까지 숫자를 그립니다.

**교훈**: "다른 것이 대신한다"는 추측으로 원작 기능을 빼지 맙니다.

## 사례 4. 아이폰에서 효과음만 안 난다

**증상**: "원래 잘 됐는데 지금 소리가 안 남. 음악은 나는데 말발굽, 때리는 소리, 일기토 효과음이 하나도 안 남."

**추적**
1. 엔진 쪽부터 의심했습니다. 브라우저 자동 시험에서 `AudioBufferSourceNode.start` 를 감싸 실제 재생 횟수를 셌습니다. 데스크톱 크롬에서는 **정상 재생**됐습니다.
2. 그래서 아이폰 쪽 문제로 좁혔습니다. 음악은 `<audio>`, 효과음은 Web Audio 입니다. 아이폰은 앱 전환·잠금 뒤 `AudioContext` 가 멈춘 채 남는 경우가 있습니다.

**수정**: 화면이 가려졌다 돌아오면 다음 터치 때 `AudioContext` 를 새로 만들고, `resume()` 이 실패해도 새로 만듭니다.

**한계**: 시험 브라우저로는 재현할 수 없어서, 실제 기기 확인을 사용자에게 부탁했습니다.

**교훈**: 엔진 → 경계 → 플랫폼 순서로 층을 나눠 확인하면, 어디가 문제인지 빨리 좁혀집니다.

## 사례 5. 장비 화면을 원작 그대로

**요청**: "아이템 정보를 보면서 착용시킬 수 있는 화면이 필요한데, 원작에서는 어디서 봤지?"

**추적**
1. 아이템 설명 글(`IMSG.E5` 기록)을 읽는 함수 → `FUN_0040ccc6`. 이 함수는 컨트롤 ID `0x42e`, `0x3f8`, `0x5c0+n` … 에 글을 씁니다.
2. `pe_dialogs.py` 로 대화상자를 뽑으니 **167 "아이템 정보"** 였습니다. 속성, 가격, 효과, 추가 효과, 설명, 장비 가능 부대 13칸으로 되어 있습니다. 같은 방법으로 **328 "장비"** 창도 찾았습니다. 창고 목록, 장수 콤보, 능력치와 변화량, 무기·방어구·보조 칸이 있습니다.
3. 창의 메시지 처리(`FUN_0046e0d3`)에서 조작을 확인했습니다.
   - 마우스 이동(0x200): 올린 아이템을 장비했을 때의 능력 변화를 미리 보여 줌 (`FUN_0046aeab`)
   - 왼쪽 놓기(0x202): 장비 / 벗기
   - 오른쪽 놓기(0x205): 아이템 정보 창
4. 미리 보기 계산(`FUN_00463dfb`)을 읽다가 **전투 능력치 버그**도 찾았습니다. 고유 무기의 추가 능력(예: 고정도 순발력 +10), 투구의 HP 보너스, 보조 장비의 병종 제한이 우리 엔진에 없었습니다.

**수정**: 두 창을 원작 배치대로 만들었습니다. 터치용으로 "한 번 = 고르기, 다시 = 장비, 길게 누르기 = 정보"를 정했습니다. 함께 찾은 전투 능력치 버그도 고쳤습니다.

**교훈**: 화면 하나를 옮기다 보면 그 화면이 쓰는 공식을 통해 다른 곳의 버그가 드러납니다.

## 사례 6. 퇴각 대사와 회심 외침

**증상**: "장수 퇴각할 때 멘트가 있는데 빠진 듯?"

**추적**
1. `IMSG.E5` 를 훑으니 649번에 `Retire Message Start ( Team Unit Only )` 라는 표지가 있었습니다. 650번부터 장수별 대사입니다. 700번대에는 공격 대사로 보이는 글이 있었습니다.
2. `650 + 인물` 을 계산하는 곳(`param + 0x28a`) → `FUN_0040c3fd` → `FUN_00443ad0` → 기본 퇴각 처리 `FUN_004438a5`. 조조군 주요 장수(인물 번호 0x1A 미만)일 때만 말합니다.
3. 700번대(`+ 700`) → `FUN_0040c4b2` → 공격 연출 시작 `FUN_00405aa4`: **회심 타격이면 25 %** 로 외칩니다. 고유 대사 21명은 표(`0x495248`)로, 나머지는 인물 기록의 목소리 종류 × 3 + 난수로 정합니다. 목소리 종류가 파일의 몇 번째 바이트인지는 로더 `FUN_00408fd5` 에서 확인했습니다.

**수정**: 퇴각 전 대사, 회심 전 외침을 넣었습니다. 대사는 기존 전투 말풍선을 씁니다.

**교훈**: 데이터 파일 안의 표지 글(개발자 메모)이 큰 실마리가 됩니다. 사람이 "빠졌다"고 한 것을 고치면서 같은 파일의 이웃 기능(회심 외침)도 함께 찾을 수 있었습니다.
