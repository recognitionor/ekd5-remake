# 3. 스크립트 엔진 (EEX)

이야기 진행, 전투 배치, 승리 조건, 대사, 증원, 일기토가 모두 **이벤트 스크립트**로 되어 있습니다. 스크립트 해석기를 정확히 만들면 게임의 대부분이 "공짜로" 돌아갑니다.

구현: `crates/ekd5/src/eex.rs` (컨테이너), `vm.rs` (인자·블록), `engine/mod.rs` (명령 실행). 시제품 디스어셈블러: `re/tools/eex.py`.

## 3.1 파일 구조

```
"EEX\0" 판(1) 하위(2)
덩어리들: (u16 종류, u16 길이, 자료)… 종류 0 = 끝
u32 절(section) 오프셋 표   (개수 = (첫 오프셋 − 표 시작) / 4)
절:   u16 블록 수, 블록들
블록: u16 길이, [머리: 조건 명령들 … op0], u16 본문 길이, 본문
본문: 명령들 … op0
```

- **단계 n**: 짝수는 `R_` 이야기, 홀수는 `S_` 전투입니다.
- **전투 절**: 0 = 배치·도입, 1 = 사건(매 순간 조건 검사), 2 = 끝.
- **사건 검사**: 절 1 의 모든 블록 머리 조건을 검사해서, 맞는 블록을 **전부 차례로** 실행합니다.
- `op1`(IF) 뒤에는 조건 명령 하나와 `u16 길이 + 중첩 본문`이 옵니다. 조건이 거짓이면 길이만큼 건너뜁니다.

## 3.2 명령 = 번호 + 인자

```
명령 = u16 번호 + 인자들
인자 = u16 표지 + 값   (표지 4 = u32, 5 = C 문자열, 그 외 = u16)
```

문제는 **명령마다 인자가 몇 개, 어떤 표지인지** 파일에 적혀 있지 않다는 것입니다. 이걸 모르면 다음 명령의 시작 위치를 알 수 없습니다.

### 인자 서명표 만들기

원작 각 명령 처리 함수는 인자를 하나씩 `FUN_0041a951(스크립트, 표지)` 로 읽습니다. 그래서:

1. 1장의 명령 표로 처리 함수를 모두 디컴파일합니다.
2. 각 함수에서 `FUN_0041a951(param_1, 0x26)` 같은 호출을 **나오는 순서대로** 모읍니다.
3. 그 표지 목록이 그 명령의 서명입니다.

```rust
// vm.rs (일부)
pub fn signature(op: u16) -> Option<&'static [u16]> {
    Some(match op {
        0 | 1 | 3 | 7 | … => &[],
        2 | 0x14 | 0x16 | … => &[5],          // 문자열 하나
        0x45 => &[0x26, 0x26, 4, 0x3E, 0x32, 2, 0x32, 2, 0x47, 0x22],
        …
    })
}
```

예외 몇 개(개수 + 목록, 부대 목록 반복)는 손으로 처리합니다.

### 117개 전수 검증

서명표가 맞는지 확인하는 가장 확실한 방법은 **모든 스크립트를 처음부터 끝까지 읽어서, 모든 블록이 정확히 경계에서 끝나는지** 보는 것입니다. 서명 하나만 틀려도 그 뒤가 전부 어긋나서 바로 드러납니다.

`re/tools/eex.py` 로 117개 파일 전부가 바이트 단위로 정확히 끝나는 것을 확인한 뒤 Rust 로 옮겼습니다.

## 3.3 명령 의미 옮기기

서명이 맞으면 인자는 읽을 수 있습니다. 다음은 **각 명령이 무엇을 하는지**입니다.

- 처리 함수를 읽고 엔진 동작으로 옮깁니다. 주석에 원작 함수를 남깁니다.
  ```rust
  // 전투 설정 (원작 FUN_004146c1): 인자 2 턴 제한, 3 전체 레벨 보정, 5 승리 목표 장수, 7 패배 목표 장수
  ```
- 인자 하나라도 무시하면 나중에 증상으로 돌아옵니다. 실제로 `op45` 의 3번 인자(전체 레벨 보정 −2)를 빼먹어서, 모든 적이 원작보다 2레벨 높았던 적이 있습니다 (8장 사례 2).
- 숫자 인자에 숨은 변환이 있을 수 있습니다. 장비 명령은 무기 = 값 − 2, 방어구 = 값 + 36, 보조 = 값 + 51 이었습니다 (8장 사례 1).

## 3.4 실행 모델

원작은 스크립트를 실행하다가 **기다리는 명령**(대사 넘기기, 이동 끝, n초 대기)에서 멈추고 화면을 갱신합니다. 엔진도 같은 구조입니다.

```
매 틱:
  기다리는 중이면 (Wait::Dialog / Ticks / Fade / …) 그 조건만 확인
  아니면 다음 명령 실행, 기다리는 명령이 나올 때까지 반복
  전투 중 스크립트가 쉬면 → 전투 진행 (내 차례 입력, AI, 연출)
  무언가 바뀌었으면 → 절 1 사건 검사
```

- 명령이 자료를 아직 못 받았으면(웹은 파일을 늦게 받음) **pc 를 되돌리고** 다음 틱에 다시 실행합니다.
- 실행 중 위치(pc, 중첩 끝 목록)를 저장 파일에 넣으면 대사 중간에서도 저장·불러오기가 됩니다.

## 3.5 모르는 명령 다루기

- 처음에는 모르는 명령을 **기록만 하고 건너뛰게** 했습니다 (`self.note(op)`). 자동 진행 시험(5장) 로그에 어떤 명령이 몇 번 나오는지 모입니다.
- 많이 나오는 것부터 옮기면 빠르게 "게임이 끝까지 가는" 상태가 됩니다.
- 화면에 아무 영향이 없는 명령(내부 표지 등)은 이유를 주석으로 남기고 비워 둡니다.
