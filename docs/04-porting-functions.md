# 4. 원작 함수를 옮기는 법

이 프로젝트의 원칙은 하나입니다. **"원작을 보고 그대로."** 그럴듯하게 지어낸 값은 결국 다시 고치게 됩니다.

## 4.1 기본 고리

```
증상 ("데미지 숫자가 안 나온다")
  → 실마리 찾기 (문자열·리소스 ID·효과음 번호·관련 함수)
  → 호출 관계를 따라 원작 함수 찾기
  → 읽고 이해하기 (구조체 칸, 보조 함수 의미)
  → 엔진에 옮기기 (주석에 FUN_ 주소)
  → 자동 진행 회귀 시험 + 그 장면 스크린샷
  → 커밋, 배포
```

## 4.2 실마리 찾는 곳

| 실마리 | 찾는 법 |
|---|---|
| 화면에 나오는 글 | `strings.txt` 또는 `pe_strings.py`. 참조하는 함수가 같이 나옴 |
| 대화상자의 칸 | `pe_dialogs.py` 로 컨트롤 ID → `grep "0x42e"` |
| 효과음 | 원작은 `FUN_004768a0(소리, 번호, 1)` 로 SE번호를 냄 → 번호로 검색 |
| 데이터 파일 | 파일 이름 문자열 → 읽는 함수 → 구조체 칸 |
| 설명 글 기록 | `IMSG` 기록 번호(예: `param + 0x28a` = 650) → 호출자 |
| 스크립트 명령 | 명령 표(1장)의 처리 함수 |

## 4.3 디컴파일 코드 읽는 요령

### 보조 함수의 정체부터 밝힌다
자주 나오는 작은 함수는 한 번 읽고 이름을 정해 두면, 이후 읽기가 훨씬 빨라집니다.

| 원작 함수 | 정체 |
|---|---|
| `FUN_00482070(n)` | 0..n−1 난수 |
| `FUN_00482090(p)` | p % 확률 (`rand(100) < p`) |
| `FUN_00481fe0(a, b)` | 0 아래로 안 내려가는 빼기 |
| `FUN_00482000(a, b, max)` | max 를 넘지 않는 더하기 |
| `FUN_0041a951(스크립트, 표지)` | 스크립트 인자 하나 읽기 |
| `FUN_004036a0(…, n)` + `FUN_0042eaa0()` | n 단위 기다리고 화면 갱신 |

### Ghidra 의 이름표를 믿지 말 것
라이브러리 함수로 잘못 인식된 이름이 있습니다. 조조전에서는 `CRichEditView::OnUpdateCharBold(&DAT_004c1128, n)` 가 실제로는 **효과음 n 재생**이었습니다. 이름보다 호출 모양과 인자를 봅니다.

### `this + 0x26` 은 메모리 구조체
2장의 함정입니다. 파일 오프셋과 다를 수 있으니 로더 함수로 대응표를 만듭니다.

### 문자 코드의 흔적
일본판에서 온 코드가 남아 있습니다. 데미지 숫자는 `0x82, 숫자 + 0x1F` 로 **Shift-JIS 전각 숫자**를 만들고 있었습니다. 한국어판 글꼴에 맞게 EUC-KR 전각 숫자로 바꿔 그렸습니다.

### 확률·순서까지 그대로
- 회심 외침: 회심 타격이면 `FUN_00482090(0x19)` = 25 %.
- 표를 찾는 반복문이 `break` 없이 끝까지 돈다면 **마지막** 일치를 쓰는 것입니다. 이런 것까지 맞춥니다.

## 4.4 시간 단위 환산

원작은 `GetTickCount / 50`, 즉 **1/20 초 단위**로 기다립니다. 일부 함수는 0.1 초 단위입니다. 엔진은 초당 30틱이므로:

- 원작 1단위 = 1.5틱
- 0.1 초 = 3틱

공격 연출을 예로 들면, 원작은 27단위 동안 2단위에 휘두르는 소리, 13단위에 맞음, 17단위에 데미지 숫자입니다. 엔진에서는 3틱, 20틱, 26틱, 41틱이 됩니다. 이렇게 환산해서 **연출의 박자**까지 원작과 같게 했습니다.

> 처음에는 엔진 틱을 그대로 써서 모든 연출이 원작보다 빨랐습니다. 사용자 피드백("원작보다 빠르다")으로 전체를 다시 환산했습니다.

## 4.5 원작 화면을 옮길 때

1. `pe_dialogs.py` 로 컨트롤 배치를 뽑습니다. 대화상자 단위(DLU)를 화면 픽셀로 바꿉니다.
2. 각 컨트롤 ID 를 채우는 함수를 찾아, 무엇을 어떤 형식으로 쓰는지 봅니다 (`wsprintf` 서식 문자열은 `pe_strings.py` 로).
3. 마우스 메시지 처리(0x200 이동, 0x202 왼쪽 놓기, 0x205 오른쪽 놓기)에서 조작 방식을 확인합니다.
4. 폰에 맞게 바꿔야 하는 부분만 바꾸고, 바꾼 이유를 문서에 남깁니다. 예: 마우스 올리기 → 한 번 누르기, 오른쪽 클릭 → 길게 누르기.

원작이 윈도 9pt 글꼴이고 우리는 16px 글꼴이라 배치는 근사입니다. **내용과 동작은 그대로** 두는 것을 우선했습니다.

## 4.6 원작과 같은지 확인하는 법

- 공식(데미지, 경험치)은 원작 함수와 **한 줄씩** 대조합니다. 분기 하나, 최솟값 하나까지 봅니다.
- 의심스러우면 같은 입력으로 계산해 봅니다. 엔진 라이브러리를 별도 작은 프로그램에서 불러, 장수 능력치와 데미지를 표로 뽑아 비교했습니다.
- 숫자로 결론 내기 전에 가정을 적습니다. 지형, 사기, 장비를 뺀 "어림값"을 실제 체감처럼 말했다가 사용자에게 바로잡힌 적이 있습니다 (7장).

## 4.7 주석과 노트

- 코드 주석에 원작 함수 주소를 남깁니다. 나중에 "왜 이렇게 했지?"를 원작으로 바로 확인할 수 있습니다.
  ```rust
  /// 물리 피해 (원작 FUN_0043dd5b). counter = 반격 (×3/4)
  ```
- `AGENTS.md` 에 원작 함수 ↔ 구현 대응, 형식 메모, **근사/미구현 목록**을 계속 갱신합니다. 미구현 목록이 있어야 "왜 빠졌지?"에 답할 수 있습니다.
